# {SYSTEM} 코어 온톨로지 연동 패키지 — 처음 읽으세요

「{SYSTEM_NAME}」 이 공개하는 **코어 온톨로지**(여러 플랫폼이 함께 쓰는 기준정보와 그 관계)를
우리 플랫폼으로 **주기적으로 받아 오는 기능**을 만들기 위한 묶음입니다. **AI 코딩 도우미**(Claude
Code · Cursor 등)에게 맡겨 만드는 것을 전제로 했습니다 — AI 가 읽을 지시서, 정답 구현, 그리고 다
만들었는지 스스로 확인할 시험장이 들어 있습니다.

- 연동 주소(API 루트): `{BASE}`
- 공개 타입: {TYPES_LONG}
- 정의 판(revision): `{REVISION}`
- 키트 판: `{KIT_VERSION}` · 생성 시각: {AT}

> 예전에 연동 키트를 받아 쓰고 있다면 `UPGRADE.md` 를 보십시오.

## 준비물

- **연동 주소와 토큰** — 공개 측 담당자에게 받습니다. 토큰은 시스템마다 따로 발급됩니다(범위
  `core:read`). 메일 본문이 아니라 별도 경로로 받으십시오.
- 우리 플랫폼 저장소를 연 **AI 코딩 도우미**.
- **Python 3.8 이상** — 시험장을 돌리는 데 씁니다. 우리 플랫폼이 다른 언어여도 필요합니다.

## 순서

1. 이 폴더를 우리 플랫폼 저장소 안에 풉니다. 예: `docs/sp-core/`
2. AI 에게 아래 문장을 그대로 붙여 넣습니다.

   ```text
   docs/sp-core/01-AI-GUIDE.md 를 처음부터 끝까지 읽고, 그대로 우리 플랫폼에
   Standard Platform 코어 온톨로지를 주기적으로 받아 오는 기능을 만들어 줘.
   구현 전에 지시서 §2 의 질문을 나에게 먼저 해 줘.
   testbed 시험장 8단계를 모두 통과하기 전에는 끝났다고 하지 마.
   ```

3. AI 가 묻는 것에 답합니다 — 받을 타입, 우리 표의 어디에 넣을지, SP 에서 사라진 것을 어떻게
   보일지, 우리 쪽에서 고친 값과 다르면 어느 쪽을 따를지, 주기, 「확인 필요」 를 누구에게 알릴지.
   모르면 AI 의 기본 제안대로 해도 됩니다.
4. **토큰은 AI 에게 채팅으로 주지 말고** 환경변수나 우리 플랫폼의 비밀 설정에 직접 넣습니다.
5. AI 의 보고에서 아래를 확인합니다.
   - [ ] 시험장 8단계 모두 통과(단계별 결과 표가 있어야 합니다)
   - [ ] 실제 SP 연결 점검 통과 — 카탈로그와 첫 수신 건수
   - [ ] 관리 화면의 「지금 받기」 버튼과 마지막 결과 표시
   - [ ] 매일 자동 실행
   - [ ] 「확인 필요」 를 받을 사람

## 운영하면서

- 결과가 **확인 필요**면 사유를 보고 공개 측 담당자에게 알립니다. 흔한 경우는 받던 타입의 공개가
  거두어졌을 때, 토큰의 범위가 바뀌어 받던 것의 절반 넘게 안 올 때입니다(이때는 정리를 멈추고
  기다립니다).
- 주 1회쯤 **처음부터 다시 받기**를 돌려 두면 표식 없이 빠진 것까지 맞춰집니다.
