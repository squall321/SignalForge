## 1. 카탈로그 — 병합이 가져온다

병합(`merge-from-drive.sh`)이 products 를 code 로 upsert 하므로 다음 dev 덤프(30분마다)가 병합되면 GWU2 가 생기고 출시일이 바뀐다.
기다리지 않으려면 손으로 한 번 병합한다(10-27 문서 2절).

```bash
set -a; source .env; set +a
PGPASSWORD=$POSTGRES_PASSWORD apptainer exec instance://sf_postgres psql -h 127.0.0.1 -p $POSTGRES_PORT -U $POSTGRES_USER -d $POSTGRES_DB -Atc "
SELECT code, released_at FROM products WHERE code IN ('GWU2','GB4','GB4P','GW9','GR2') ORDER BY code;"
# 기대: GB4 2026-03-11 · GB4P 2026-03-11 · GR2 (빈칸) · GW9 2026-08-07 · GWU2 2026-08-07
```

alembic 기록을 맞추려면 `SF_MIGRATE=1 bash scripts/up.sh` 로 0048 을 돈다(멱등 — 병합과 겹쳐도 code 로 한 행이다).

병합은 dev 가 아는 글의 링크를 dev 와 같게 맞춘다(dev 가 뗀 링크는 뗀다). 같은 날 dev 가 경쟁사 웨어러블 서브레딧 7곳의 2026년

(병합 잠금이 겹친 차례를 건너뛰게 한다 — 10-27 문서 2절).


## 3. sf-mcp 다시 띄우기 — 질의 해석이 새 매처를 쓴다

MCP 는 크롤러의 제품 매처로 질의를 푼다('갤럭시 링 배터리' → GR1, '애플워치 울트라처럼' → 애플). update-all 이 sf-mcp 를 다시
띄우지 않았다면 11-07 문서 4절처럼 워치독 락을 쥐고 띄운다.

```bash
apptainer exec instance://sf-mcp sh -c 'cd /mcp-server && python3 -c "
import sys; sys.path.insert(0, \"/crawler\")
from base.product_match import infer_all_product_codes as f
print([c for c, _ in f(\"갤럭시 링 배터리\")], [c for c, _ in f(\"애플워치 울트라처럼 비싸질까\")], [c for c, _ in f(\"Galaxy Watch Ultra 2\")])"'
# 기대: ['GR1'] ['AWU1'] ['GWU2']
```

## 4. DB 비밀번호 — 공개 기본값과 같다면 바꾼다

dev 의 Postgres · Redis 비밀번호는 공개 리포 `.env.example` 의 기본값과 같았고, Postgres 는 모든 인터페이스에서 들었다(2026-11-14
dev 는 바꾸고 루프백에만 묶었다). cae00 도 같은지 받은 편지함 Q1 의 읽기 명령으로 본다. **다르면 이 절은 건너뛴다.**

같다면 — 값은 화면 · 명령줄에 남기지 않는다(표준입력으로 넘긴다).

```bash
set -a; source .env; set +a
mkdir -p ~/.config/signalforge && chmod 700 ~/.config/signalforge
cp -p .env ~/.config/signalforge/env.bak-$(date +%Y%m%d) && chmod 600 ~/.config/signalforge/env.bak-*
NEW="$(python3 -c 'import secrets; print(secrets.token_hex(24))')"
printf "ALTER ROLE %s PASSWORD '%s';\nALTER SYSTEM SET listen_addresses = 'localhost';\n" "$POSTGRES_USER" "$NEW" \
  | PGPASSWORD=$POSTGRES_PASSWORD apptainer exec instance://sf_postgres psql -h 127.0.0.1 -p $POSTGRES_PORT -U $POSTGRES_USER -d $POSTGRES_DB -v ON_ERROR_STOP=1 -q -f -
OLD="$POSTGRES_PASSWORD" NEW="$NEW" python3 -c "
import os, pathlib
p = pathlib.Path('.env'); s = p.read_text(); n = s.count(os.environ['OLD'])
p.write_text(s.replace(os.environ['OLD'], os.environ['NEW'])); print('.env', n, '곳 바꿈')"
chmod 600 .env backend/.env
```

그다음 postgres 와 DB 를 쓰는 서비스를 다시 띄운다(11-07 문서 4절의 워치독 락 그대로 — 인스턴스는 sf-mcp · sf-backend · sf_postgres).
병합 · plm-sync · embed-new cron 은 실행마다 `.env` 를 읽으므로 따로 할 것이 없다.

**확인** — 5434 가 루프백에서만 듣는지, 바깥 주소 접속이 거절되는지, 새 비밀번호로 서비스가 붙는지.

```bash
ss -ltn | awk '$4 ~ /:5434$/ {print $4}'                     # 기대: 127.0.0.1:5434 (와 [::1]:5434) 만
IP=$(hostname -I | awk '{print $1}'); timeout 5 bash -c "exec 3<>/dev/tcp/$IP/5434" 2>/dev/null && echo "열림(문제)" || echo "거절됨"
curl -s -o /dev/null -w '%{http_code}\n' -H "X-API-Key: $API_KEY" "http://127.0.0.1:${API_PORT:-8000}/api/v1/alerts/rules"   # 200
```
