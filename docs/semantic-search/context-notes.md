# 시맨틱 검색 작업 노트 (2026-10-17)

## 출발점

- 요청 — "온톨로지화되어 검색할 때 알아서 시맨틱 검색이 되게끔".
- 지금 검색(search_voc)은 글자 일치다. 제품명 표기만 바뀌어도 100배 흔들린다
  ('S25 Ultra' 9,680 · '갤럭시 S25 울트라' 88). 증상도 마찬가지 — '발열' 과
  'overheating' 은 서로를 못 찾는다.
- 그런데 말뭉치는 이미 개념으로 주석돼 있다 — 제품(voc_product_links 47.6만),
  결함 부품×증상(voc_defects 9.5만행), 주제(categories, 활성 71%). 질의만 같은
  개념 공간으로 옮기면 된다.

## 자원 실측

- PostgreSQL 16 (Alpine) — pgvector 없음. pg_trgm·unaccent·fuzzystrmatch 는 설치 가능.
- GPU RTX 5070 Ti 16GB (3GB 사용 중). ollama 에 임베딩 모델 없음(qwen2.5 등 생성 모델만).
- 그래서 1단계는 임베딩 없이 간다. 2단계는 사용자 결정 사항으로 남긴다.

## 결정

- **사전을 복제하지 않는다.** 제품 매처·결함 렉시콘·주제 사전은 crawler 에 정본이 있다.
  MCP 에 옮겨 적으면 갈라진다(keyword_match 가 그 전례). MCP 컨테이너에 /crawler 를
  바인드하고 shared/ontology.py 가 정본을 import 한다. backend 는 이미 /crawler 를 본다.
- **온톨로지 핵심은 DB 를 모른다**(shared/ontology.py). SQL 은 MCP 쪽(tools/semantic.py)이
  만든다 — 해석은 단위 테스트로, 검색은 실DB 테스트로 나눠 검증한다.
- **질의 쪽 짧은 표현은 따로 둔다.** 문서용 렉시콘은 정밀도 때문에 문맥을 요구한다
  ('dust' 단독은 방진 스펙이라 '유입 문맥' 필수). 질의에서는 사용자가 뜻을 직접 말했으니
  '먼지'·'주름'·'기포' 단독도 그 증상이다. 반대로 본문 동의어 검색에는 정밀한 것만 쓴다
  ('hot'·'slow' 는 질의 인식에는 쓰되 본문 검색어로는 쓰지 않는다).
- **채널은 장소 표지가 있을 때만 필터.** '유튜브 앱 튕김' 의 유튜브는 앱 이름이다.
  '유튜브에서'·'레딧 반응'·'on reddit' 처럼 장소로 쓸 때만 플랫폼을 좁힌다.
- **시장은 국가 OR 언어.** country_code 의 US 96% 가 플랫폼 기본값이라 국가만으로는
  틀린다. '한국' 은 country_code='KR' 또는 language_detected='ko' 로 본다.
- **감성어는 필터가 아니라 가산점.** '불만' 이라고 했다고 negative 로 거르면 감성 분류기가
  중립으로 둔 실제 불만이 빠진다.
- **남는 말(잔여어)은 가산점.** 개념이 범위를 정하고, 사전에 없는 말은 순위만 올린다.
  개념이 하나도 없으면 기존 키워드 검색으로 그대로 간다(퇴행 없음).
- **세대(시리즈)는 표지가 있을 때만.** 'S25' 는 기본 모델, 'S25 시리즈'·'S25 라인업' 은
  S25·S25+·S25 Ultra·S25 FE 전부(S25 Edge 는 카탈로그에서 S25 로 흡수돼 있다). 해석 결과에
  대안으로 알려준다.

## 구조

```
질의 ──ontology.interpret──▶ 개념 (shared/ontology.py, DB 모름)
       채널(장소 표지) → 제품(라이브 → 질의 약칭 → 레거시) → 세대 표지 → 시리즈·폼팩터·기기·브랜드
       → 증상·부품(같은 낱말이 둘 다일 수 있어 구간은 나중에 차지) → 주제 → 관계(함의 부품·주제)
       → 비교 의도 → 시장 → 감성·기간·연도 → 잔여어
     ──semantic._resolve────▶ 범위 (카탈로그로 코드→id, 세대 확장, 시리즈·폼팩터·브랜드·기기)
     ──semantic._build_sql──▶ 후보 = 결함 주석 ∪ 동의어(FTS 하나 + 한국어 원문 부분일치) ∪ 주제
                              순위 = 주석·동의어 점수 + 제품 역할(대표 2·비교 1·언급 0.5) + 가산
```

## 실측과 고친 함정 (활성 99만 행)

| 질의 | 처음 | 고친 뒤 | 원인 |
|---|---|---|---|
| 발열 (전역) | 20초 시간 초과 | 0.6초 | 불용어 구절 — phraseto('too hot') = 'hot', ('heats up') = 'heat' |
| 발열 | 2.9초 | 0.6초 | 후보 7천 건 본문을 통째로 정렬 — 순위는 좁은 열로, 본문은 상위 N 만 |
| 태블릿 화면 깜빡임 | 17초 | 1.2초 | CTE 통계 없음 → 3만 행 범위에서 행마다 to_tsvector |
| 삼성 발열 | 8초 → 17초 | 1.5~3.8초 | 브랜드 전체 CTE(수십만 행), 후보마다 to_tsvector → 후보 필터 + ILIKE |
| S25 울트라 발열 | 8.6초(첫 호출) | 0.4초 | 위 고침의 합 |

- 범위 크기는 질의마다 먼저 잰다(링크 수, 인덱스만 읽어 수십 ms). 1.5만 이하는 범위가 후보를
  몰고, 6만 이하는 범위 CTE + 인덱스 후보, 그 위는 후보에 필터.
- 15초를 넘기면 실패하지 않고 본문 동의어 없이 주석만으로 다시 찾는다(notes 에 남긴다).

## 검증

- 같은 뜻 4표기('S25 울트라 발열' · 'Galaxy S25 Ultra overheating' · 's25u 발열' · '갤럭시 S25
  울트라 과열') → 같은 251건, 같은 순위 (test_semantic_search).
- 범위 — 'S25 울트라 발열' 상위 30건 전부 GS25U 링크, 90% 이상이 발열 근거.
- '폴드7 힌지 먼지' 상위 10건 중 GZF7 대표 글 7건 이상 (제품 역할 가중 전에는 폴드8 기사가 위).
- 비교 — 'S25 vs 아이폰 16 배터리' 결과 전부 두 제품 모두에 링크.
- 바인드 없이 띄우면 서버는 살고 검색만 키워드로 — 테스트는 이유를 적고 skip(84 passed · 2 skipped).
- mcp-server 127 passed, crawler 호스트 1824 / 컨테이너 1715 passed(실패는 기존 7·4건 그대로).

## 한계 (2단계 후보)

- 사전에 없는 바꿔 말하기는 못 잡는다 — '폰이 손난로 같다'(발열), '하루를 못 버틴다'(광탈).
  임베딩 벡터 검색이 필요하다. GPU(RTX 5070 Ti 16GB)는 있으나 pgvector·임베딩 모델이 없다.
  pgvector 없이도 numpy 행렬(100만×1024 float16 ≈ 2GB)로 전수 코사인이 100ms 안팎이라 가능하다.
- 감성어는 가산일 뿐이라 '불만' 을 붙여도 중립 글이 섞인다(감성 분류기 한계도 있다 —
  '발열 심하다 느껴본 적이 없네요' 가 negative).
- 결함 주석 자체의 부정 처리 한계가 그대로 들어온다(위 예가 발열 결함으로 주석됨).
