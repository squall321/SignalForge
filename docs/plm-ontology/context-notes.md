# 과제·개발모델 온톨로지 작업 노트 (2026-10-23)

## 조사 — StepForge 와 SP

- SP 는 도메인이 빈 사내 플랫폼 틀이다. 도메인은 온톨로지 메타모델(타입·칸·관계)로 얹는다. PLM 정의는
  `StandardPlatform/pipeline/core/plm-core.json`.
  - `plm_project` 프로젝트 — key.
  - `plm_task` 과제 — key = **과제코드**, label = **과제명**(개발명 + 차수 접미어 — 예시 표 '감마_C2'·'베타_12').
  - `plm_model` 개발모델 — key = **개발모델명 원문**(예시 `SM-X200B_NA_C2_ATT`), `task`(→ 과제), `model_kind`(Basic·RC·파생),
    `product_text`, `mass_model_code`(양산모델코드), 모델명 해석(`base_code`·`series`·`rc_marker`·`region`·`model_revision`·`carrier`).
  - 관계 `plm_derived_from` 파생 → 원 모델.
- 받는 길 — 허브의 코어 API. `GET {base}/core`(카탈로그) · `GET {base}/core/{type}?limit&since&cursor` →
  `{items, next, as_of, reset}` · `Authorization: Bearer <core:read>` · 401/403 중단 · 429/5xx 재시도 · 404 는 둘
  (`-CORE-0001` 공개 안 된 타입 · `-CORE-0002` 커서를 못 읽음).
- **실제 허브 연결은 아직 어디에도 없다.** StepForge 10-23 문서도 `STEPFORGE_SP_CORE_URL` 빈 값("PLM 동기화 끔,
  cae00 과 같다"). 그래서 이번 작업은 수신자를 만들어 두고 끈 채로 둔다 — 주소·토큰이 오면 켠다.

## 결정

- **모델코드 사전이 먼저다.** PLM 의 개발모델이 SignalForge 제품에 닿는 길은 기본 모델코드뿐이다. 사전은 PLM 없이도
  쓸모가 있다(본문 태깅·'SM-S938B' 질의).
- **수신은 매번 전체 스냅샷 + 원자 교체.** StepForge 는 증분(since·as_of) + 수신 규칙 열하나를 지킨다. SignalForge 는
  조회용 현재 상태만 필요하다 — 이력도 쓰기도 없다. 전체를 받아 임시 파일에 쓰고 끝까지 받았을 때만 `os.replace`
  한다. 도중 실패는 옛 거울을 그대로 둔다(StepForge 가 짚은 "reset 에 먼저 비우면 그동안 답을 잃는다" 를 피한다).
  as_of 보존·reset·부재 대조·되살림 규칙이 필요 없어진다. 남기는 것 — key upsert, `deleted`·`hidden` 은 싣지 않음,
  모르는 칸 무시, `previous_keys` 는 옛 과제코드로도 찾게 별칭으로, 401/403·404 둘·재시도.
- **급감 보류** — 새 스냅샷의 한 타입이 옛 것의 절반 아래로 줄면(옛 것 10건 이상) 교체하지 않고 알린다. 토큰의 부서·
  공개 범위가 바뀌어 반이 사라진 것을 "과제가 없어졌다" 로 믿지 않는다(StepForge 규칙 7 의 문턱과 같다).
- **토큰은 파일로만** — `crawler/data/plm/sp_token`(한 줄, gitignore 된 data/ 아래, Drive 동기화 대상 아님) 또는
  `SF_SP_TOKEN_FILE`. `.env` 에 두지 않는다 — up.sh 가 .env 전부를 모든 컨테이너 환경으로 내보낸다. 주소는
  `.env` 의 `SF_SP_CORE_URL`(비밀 아님).
- **과제명은 질의에서만 쓴다.** 본문 태깅에 과제명(개발명)을 쓰면 흔한 낱말과 겹친다. 과제코드는 공개 글에 나오지
  않는다. 본문 태깅은 모델코드만.

## 결정 — 질의 해석

- **단일 제품은 이름과 같은 자리(products), 여럿은 한 묶음(product_sets).** 'SM-S938B 발열' 이 'S25 울트라 발열' 과
  해석·SQL 이 같아 결과가 같다. 출시 전 세대·제품 여럿에 걸린 과제는 묶음 하나 — 'vs' 비교 판정이 묶음을 하나로 센다
  (낱개로 넣으면 "넷을 다 언급한 글" 이 됐다).
- **제품이 함의한 브랜드 말은 남는 말이 아니다.** '삼성 S25 울트라 발열' 이 '삼성' 을 남는 말로 남겨 벡터·가산이 붙고
  'S25 울트라 발열' 과 결과가 갈렸다 — 1단계부터 있던 결함이다(불변성 시험 표기에 브랜드 말이 없어 안 보였다).
  다른 브랜드('삼성 vs 아이폰 16')는 그대로 둔다.
- **PLM 은 인자로 받는다** — `interpret(..., plm=)`. 해석 함수는 파일을 읽지 않는다(시험이 가짜 색인을 넘긴다).
- **과제를 제품에 못 이으면 그 말은 남는 말로 둔다** — 출시 전 신모델은 본문에 개발명이 나오는 유출 글이 있다.
  알림에 사전에 없는 기본 코드를 적는다(사전을 늘릴 근거).

## 재기동 경합 (2026-10-23)

- 인스턴스를 하나씩 멈추는 동안 워치독(매분)이 "레지스트리 유실(고아)" 로 보고 끊고 up.sh 를 불러 내 up.sh 와 겹쳤다.
  그 뒤 **옛 supervisor 가 SIGTERM 으로 끝나며 정리 처리기가 같은 이름의 레지스트리를 지웠다** — 막 뜬 새 인스턴스가
  고아가 되고, 워치독이 그것을 또 끊는 고리가 돌았다(beat 세 번).
- 끊는 법 — 남은 옛 supervisor 트리(starter·appinit·squashfuse)를 **SIGKILL** 로. 처리기가 안 돌아 새 레지스트리가 남는다.
  한 번에 수렴했다(supervisor 1 · beat 1 · 레지스트리 있음 · 워치독 한 바퀴 조용).
- 워치독 쪽 개선 여지 — 고아 판정에서 TERM 뒤 supervisor 가 실제로 끝날 때까지 기다린 뒤 up.sh 를 부르면 겹치지 않는다.
  이번에는 고치지 않았다(복구 계층이라 따로 시험과 함께).
