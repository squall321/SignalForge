# cae00 배포 적용 체크리스트 — 2026-10-17

이 문서는 **cae00(배포서버)에서 작업하는 AI/운영자**를 대상으로 한다.
[2026-10-15 체크리스트](DEPLOY_CAE00_2026-10-15.md) 이후 dev 박스에서 고친 것 중
`git pull` **만으로는 적용되지 않는 것**이다. 10-15 문서를 아직 적용하지 않았다면
그것부터 하라(사전 준비 — `XDG_RUNTIME_DIR`·`DBUS_SESSION_BUS_ADDRESS` 설정도 거기 있다).

각 항목은 `확인` → `조치` 순이다. 확인을 먼저 돌려 필요한 것만 적용하라. 전부 멱등이다.
아래 수치는 모두 dev 박스 실측값이다.

## 무엇이 바뀌었나

사용자 제보 — AI 로 검색할 때마다 "제품 태깅이 거의 안 되어 있다"는 말이 나온다.

1. **MCP 도구 설명이 낡았다** (`58c2f23`). `get_unmapped_voc` 설명에 2026-06 수치
   "전체의 ~82% 를 차지하는 미태깅분"이 남아 있었고, 호출한 AI 가 그걸 사실로 옮겼다.
   실측은 활성 991,882건 중 33.3% 태깅이다. 이제 설명에 숫자를 두지 않고 도구가
   `coverage` 필드로 실측값을 돌려준다.
2. **구형 모델 태깅이 08-28 부터 멈춰 있었다** (`51e69a5`). Note 9·S10·Watch4·Tab S9·
   A53·Pixel 7 같은 구형 311종은 레거시 사전을 쓰는 재태깅 잡(reprocess Phase C)에만
   의존했는데, 08-28 번역 수정이 그 잡을 스케줄에서 뺐다. 이제 수집·링크 백필이 모두
   지나는 `infer_all_product_codes` 안에서 게이트를 거쳐 돈다(홀드아웃 정밀도 98.8%).

3. **시맨틱 검색** (`9fad381`). `search_voc` 가 검색어를 온톨로지 개념(제품·세대·부품·증상·
   주제·시장·채널)으로 바꿔 찾는다 — 'S25 울트라 발열' 과 'Galaxy S25 Ultra overheating' 이
   같은 결과. `semantic_search`·`get_ontology` 도구가 추가돼 37개가 된다. **sf-mcp 에
   `/crawler` 바인드가 새로 필요하다**(up.sh 에 들어 있다 — up.sh 로 다시 띄우면 된다).

4. **시맨틱 검색 2단계** (`dd825ad`, 순위 보정 `24ba95b`·`c0033ff` — 코드만이라 1절의 sf-mcp 재기동이면 된다). 사전 밖 표현 — 은유('폰이 손난로 같아요')는
   로컬 LLM 이 증상 개념으로 옮기고, 비슷한 문장은 임베딩 벡터로 찾는다. ollama 모델 2개와
   벡터 색인이 필요하다(없으면 1단계로 조용히 강등) — 4절.
5. **Galaxy A14·A15 카탈로그 + 일반명 1세대 태그 정리** (`7b09887`). 마이그레이션 0044 — 5절.

모두 **실행 중인 인스턴스는 코드를 다시 읽지 않는다.** 재기동해야 반영된다.

## 1. sf-mcp 재기동 — 사용자가 직접 겪는 증상이 이것이다

**확인** — 지금 떠 있는 MCP 가 옛 설명을 내보내는지 본다.

```bash
set -a; source .env; set +a
P="${MCP_PORT:-8013}"
H=(-H "Content-Type: application/json" -H "Accept: application/json, text/event-stream")
[ -n "${SF_MCP_TOKEN:-}" ] && H+=(-H "Authorization: Bearer $SF_MCP_TOKEN")
SID=$(curl -s -D - -o /dev/null "${H[@]}" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}' \
  | awk -F': ' 'tolower($1)=="mcp-session-id"{print $2}' | tr -d '\r')
curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}' >/dev/null
curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | grep -o '전체의 ~82%' | head -1
# 출력이 '전체의 ~82%' 면 옛 코드다 → 조치. 아무것도 안 나오면 이미 반영됐다.
```

**조치** — 인스턴스는 **하나씩** stop 한다(여러 개를 한 번에 넘기면 조용히 실패한다).

```bash
apptainer instance stop sf-mcp
for i in $(seq 1 25); do ss -ltn | grep -qE "[:.]${MCP_PORT:-8013}\b" || break; sleep 1; done
bash scripts/up.sh
```

**검증** — 위 확인 명령을 다시 돌려 출력이 비어야 한다. 이어서 바인드와 시맨틱 검색을 본다.

```bash
apptainer exec instance://sf-mcp sh -c 'ls -d /crawler/base /shared/ontology.py' 2>&1 | grep -v '^INFO:'
# 기대: 두 경로 모두 보인다. 없으면 up.sh 가 옛 것이다 — git pull 후 다시 1. 조치

curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"semantic_search","arguments":{"query":"S25 울트라 발열","limit":3}}}' \
  | sed -n 's/^data: //p' \
  | python3 -c "import json,sys; r=json.loads(json.loads(sys.stdin.read())['result']['content'][0]['text']); print(r['strategy'], r['total'])"
# 기대: semantic. keyword 면 결과의 notes 에 원인(온톨로지 import 실패 등)이 있다.
```

dev 박스에서는 재기동 후 도구 37개, `semantic_search('S25 울트라 발열')` 이 251건을 냈다.

## 2. sf-crawler-worker 재기동 — cae00 에서 수집을 돌릴 때만

cae00 의 DB 가 dev 의 덤프로 복원되는 구조(auto-pull)라면 수집 worker 가 없거나 의미가
없다 — 이 항목은 건너뛰어도 된다. cae00 이 **직접 수집**한다면 재기동해야 새 글에
구형 모델이 태깅된다.

**확인**

```bash
apptainer exec instance://sf-crawler-worker sh -c "cd /crawler && python3 -c '
from base.product_match import infer_all_product_codes as f
print(f(\"Samsung opens Galaxy Note 9 reservations\"))'" 2>&1 | grep -v '^INFO:'
# 기대: [('GN9', 'primary')]   — 옛 코드면 []
```

`exec` 는 새 파이썬을 띄우므로 위 확인은 **코드가 받아졌는지**만 보여준다. 이미 떠 있는
celery worker 는 옛 모듈을 들고 있으니, 수집을 돌린다면 확인 결과와 상관없이 재기동한다.

**조치**

```bash
apptainer instance stop sf-crawler-worker
for i in $(seq 1 25); do ps -eo args | grep -q '[c]elery -A celery_app worker' || break; sleep 1; done
bash scripts/up.sh
```

## 3. DB — 대부분 조치 불필요

- **dev 덤프로 복원하는 경우**: dev 가 2026-10-17 에 기존 미태깅 행을 다시 태깅했다
  (결과는 [context-notes](product-tagging/context-notes.md)). 다음 덤프 수신 때 그대로 넘어온다.
- **cae00 DB 가 독립인 경우**: 별도 작업이 필요 없다. 매일 03:30 의 귀속 보강
  (`scripts/enrich-backfill.sh` → `backfill_product_links`, 하루 6만 행)이 이제 같은
  폴백을 거치므로 약 17일에 걸쳐 코퍼스 전체에 반영된다.

**확인** (어느 경우든)

```bash
set -a; source .env; set +a
apptainer exec instance://sf_postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -h 127.0.0.1 -p "${POSTGRES_PORT}" -c "
SELECT to_char(date_trunc('month', v.collected_at),'YYYY-MM') AS m,
       round(100.0*count(*) FILTER (WHERE p.is_active = false)/count(*),2) AS old_model_pct
FROM voc_records v LEFT JOIN products p ON p.id = v.product_id
WHERE v.archived_at IS NULL AND v.collected_at >= '2026-08-01'
GROUP BY 1 ORDER BY 1"
# 고장 상태: 8월 8% 대 → 9·10월 1~2% 로 꺼진다. 반영 후에는 9·10월이 다시 올라온다.
```

## 4. 시맨틱 검색 2단계 — ollama 모델과 벡터 색인 (선택, 없어도 검색은 돈다)

dev 에서 같은 날 2단계를 붙였다 — 사전에 없는 표현(은유·바꿔 말하기)을 찾는다.
**없어도 1단계(온톨로지) 검색은 그대로 동작한다.** 둘 다 없으면 결과의
`interpretation.vector.used` 가 false, `llm_symptoms` 가 [] 일 뿐이다.

| 구성 | 쓰임 | 없으면 |
|---|---|---|
| ollama `qwen2.5:7b` | 은유 → 증상 개념 ('폰이 손난로 같아요' → 발열) | 은유 질의가 개념 없이 간다 |
| ollama `bge-m3` (1.2GB) | 질의·본문 임베딩 | 벡터 경로가 빠진다 |
| `crawler/data/vectors/bge-m3/` | 본문 벡터 100만 행(약 4GB) | 벡터 경로가 빠진다 |

**확인**

```bash
curl -s --max-time 5 http://127.0.0.1:11434/api/tags | python3 -c \
  "import json,sys; print([m['name'] for m in json.load(sys.stdin)['models']])"
# bge-m3·qwen2.5:7b 가 있는가
python3 -c "import json; m=json.load(open('crawler/data/vectors/bge-m3/manifest.json')); print(m['count'], m['cursor'])"
# 색인 행 수 · 커서
```

**조치** — cae00 에 GPU 가 있으면 직접 만든다(dev 실측 190건/초 → 약 1.5시간).

```bash
ollama pull bge-m3 && ollama pull qwen2.5:7b      # 첫 pull 이 503 이면 다시 — dev 에서도 한 번 났다
set -a; source .env; set +a
DB="postgresql+asyncpg://${POSTGRES_USER}:${POSTGRES_PASSWORD}@127.0.0.1:${POSTGRES_PORT}/${POSTGRES_DB}"
nohup apptainer exec --bind "$PWD/crawler:/crawler" --env DATABASE_URL="$DB" \
  apptainer/sif/crawler.sif sh -c "cd /crawler && python3 scripts/build_embeddings.py" \
  > logs/build-embeddings.log 2>&1 &
# 커서가 manifest 에 남으므로 끊겨도 다시 돌리면 이어간다. 이후 증분은 beat 'embed-new-2h'.
```

GPU 가 없으면 100만 행 임베딩은 CPU 로 오래 걸린다(dev 에서는 재지 않았다). **DB 가 dev 덤프로
복원되는 구조일 때만** dev 의 `crawler/data/vectors/bge-m3/` 를 통째로 복사해 와도 된다 — 벡터는
`voc_records.id` 로 붙으므로 id 가 같아야 한다. **cae00 이 독립 DB 로 직접 수집한다면 복사하지
마라** — 다른 글에 엉뚱한 벡터가 붙는다. 그때는 위처럼 직접 만들거나 2단계 없이 쓴다.
색인을 복사해 왔어도 검색 때 질의 한 건을 임베딩할 ollama(bge-m3)는 cae00 에 있어야 한다
(8초 안에 못 받으면 그 질의는 벡터 없이 간다). ollama 자체가 없으면 2단계 없이 쓴다.

**재기동** — 증분 스케줄(`embed-new-2h`)은 beat 가, 실행은 worker 가 새 코드를 읽어야 돈다.
1절의 sf-mcp 에 더해 둘 다 하나씩 재기동한다.

```bash
for i in sf-crawler-beat sf-crawler-worker; do
  apptainer instance stop "$i"
  for t in $(seq 1 25); do ps -eo args | grep -q "[A]pptainer instance: $(id -un) \[$i\]" || break; sleep 1; done
done
bash scripts/up.sh
```

**검증** — 은유 질의가 LLM 개념과 벡터를 쓰는지 본다(1절의 세션 변수 그대로).

```bash
curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":4,"method":"tools/call","params":{"name":"semantic_search","arguments":{"query":"폰이 손난로 같아요","limit":3}}}' \
  | sed -n 's/^data: //p' \
  | python3 -c "import json,sys; r=json.loads(json.loads(sys.stdin.read())['result']['content'][0]['text']); i=r.get('interpretation',{}); print(r['strategy'], i.get('llm_symptoms'), i.get('vector',{}).get('used'))"
# dev 실측: semantic ['overheat'] True.  ['overheat'] 가 [] 면 qwen2.5:7b, True 가 False 면 bge-m3·색인을 본다.
```

dev 덤프를 복원하는 구조면 **조치 불필요** — 덤프에 0044 와 태깅 결과가 들어 있다.
독립 DB 라면 마이그레이션을 돌린다.

## 참고 — 남은 것

- 일반명 1세대 태그(GZF1·GB1·GN1 등) 중 2세대 출시 + 180일 이전 글, 1세대를 명시한 글,
  발행일이 없는 글은 일부러 남겼다. 그 시기의 '갤럭시 폴드' 는 실제로 1세대다.
- 브랜드·전역 질의('갤럭시 …', '삼성 …', 제품 없는 증상)는 캐시가 식으면 6~16초, 따뜻하면 1초다.
  PG `shared_buffers` 가 기본 128MB 라 거의 전부 OS 페이지 캐시에 기대고, dev 는 스왑이 꽉 차
  캐시가 몇 분 만에 갈린다. DB 3.5GB 중 주로 읽히는 건 voc_records 1.5GB 다. **cae00 은 올린다 —
  [2026-10-18 체크리스트](DEPLOY_CAE00_2026-10-18.md)**(dev 는 OOM 위험으로 그대로). 15초를 넘기면
  주석만으로 다시 찾으므로 검색이 실패하지는 않는다.
- 벡터 색인은 적재 시점의 활성 행만 담는다. 나중에 보관(archive)된 행은 SQL 이 걸러내고,
  보관이 풀린 행은 다음 전량 재적재 때 들어간다(드물다).
