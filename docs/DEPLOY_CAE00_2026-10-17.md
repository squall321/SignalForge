# cae00 배포 적용 체크리스트 — 2026-10-17

이 문서는 **cae00(배포서버)에서 작업하는 AI/운영자**를 대상으로 한다.
[2026-10-15 체크리스트](DEPLOY_CAE00_2026-10-15.md) 이후 dev 박스에서 고친 것 중
`git pull` **만으로는 적용되지 않는 것**이다. 10-15 문서를 아직 적용하지 않았다면
그것부터 하라(사전 준비 — `XDG_RUNTIME_DIR`·`DBUS_SESSION_BUS_ADDRESS` 설정도 거기 있다).

각 항목은 `확인` → `조치` 순이다. 확인을 먼저 돌려 필요한 것만 적용하라. 전부 멱등이다.
아래 수치는 모두 dev 박스 실측값이다.

## 무엇이 바뀌었나

사용자 제보 — AI 로 검색할 때마다 "제품 태깅이 거의 안 되어 있다"는 말이 나온다.

1. **MCP 도구 설명이 낡았다** (`58c2f23`). `get_unmapped_voc` 설명에 2026-06 수치
   "전체의 ~82% 를 차지하는 미태깅분"이 남아 있었고, 호출한 AI 가 그걸 사실로 옮겼다.
   실측은 활성 991,882건 중 33.3% 태깅이다. 이제 설명에 숫자를 두지 않고 도구가
   `coverage` 필드로 실측값을 돌려준다.
2. **구형 모델 태깅이 08-28 부터 멈춰 있었다** (`51e69a5`). Note 9·S10·Watch4·Tab S9·
   A53·Pixel 7 같은 구형 311종은 레거시 사전을 쓰는 재태깅 잡(reprocess Phase C)에만
   의존했는데, 08-28 번역 수정이 그 잡을 스케줄에서 뺐다. 이제 수집·링크 백필이 모두
   지나는 `infer_all_product_codes` 안에서 게이트를 거쳐 돈다(홀드아웃 정밀도 98.8%).

둘 다 **실행 중인 인스턴스는 코드를 다시 읽지 않는다.** 재기동해야 반영된다.

## 1. sf-mcp 재기동 — 사용자가 직접 겪는 증상이 이것이다

**확인** — 지금 떠 있는 MCP 가 옛 설명을 내보내는지 본다.

```bash
set -a; source .env; set +a
P="${MCP_PORT:-8013}"
H=(-H "Content-Type: application/json" -H "Accept: application/json, text/event-stream")
[ -n "${SF_MCP_TOKEN:-}" ] && H+=(-H "Authorization: Bearer $SF_MCP_TOKEN")
SID=$(curl -s -D - -o /dev/null "${H[@]}" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-03-26","capabilities":{},"clientInfo":{"name":"check","version":"1"}}}' \
  | awk -F': ' 'tolower($1)=="mcp-session-id"{print $2}' | tr -d '\r')
curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}' >/dev/null
curl -s "${H[@]}" -H "mcp-session-id: $SID" -X POST "http://127.0.0.1:$P/mcp" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}' | grep -o '전체의 ~82%' | head -1
# 출력이 '전체의 ~82%' 면 옛 코드다 → 조치. 아무것도 안 나오면 이미 반영됐다.
```

**조치** — 인스턴스는 **하나씩** stop 한다(여러 개를 한 번에 넘기면 조용히 실패한다).

```bash
apptainer instance stop sf-mcp
for i in $(seq 1 25); do ss -ltn | grep -qE "[:.]${MCP_PORT:-8013}\b" || break; sleep 1; done
bash scripts/up.sh
```

**검증** — 위 확인 명령을 다시 돌려 출력이 비어야 한다. dev 박스에서는 재기동 후
도구 35개, `get_unmapped_voc` 설명이 "현재 태깅률(coverage)과 미태깅분 진단"으로 바뀌었다.

## 2. sf-crawler-worker 재기동 — cae00 에서 수집을 돌릴 때만

cae00 의 DB 가 dev 의 덤프로 복원되는 구조(auto-pull)라면 수집 worker 가 없거나 의미가
없다 — 이 항목은 건너뛰어도 된다. cae00 이 **직접 수집**한다면 재기동해야 새 글에
구형 모델이 태깅된다.

**확인**

```bash
apptainer exec instance://sf-crawler-worker sh -c "cd /crawler && python3 -c '
from base.product_match import infer_all_product_codes as f
print(f(\"Samsung opens Galaxy Note 9 reservations\"))'" 2>&1 | grep -v '^INFO:'
# 기대: [('GN9', 'primary')]   — 옛 코드면 []
```

`exec` 는 새 파이썬을 띄우므로 위 확인은 **코드가 받아졌는지**만 보여준다. 이미 떠 있는
celery worker 는 옛 모듈을 들고 있으니, 수집을 돌린다면 확인 결과와 상관없이 재기동한다.

**조치**

```bash
apptainer instance stop sf-crawler-worker
for i in $(seq 1 25); do ps -eo args | grep -q '[c]elery -A celery_app worker' || break; sleep 1; done
bash scripts/up.sh
```

## 3. DB — 대부분 조치 불필요

- **dev 덤프로 복원하는 경우**: dev 가 2026-10-17 에 기존 미태깅 행을 다시 태깅했다
  (결과는 [context-notes](product-tagging/context-notes.md)). 다음 덤프 수신 때 그대로 넘어온다.
- **cae00 DB 가 독립인 경우**: 별도 작업이 필요 없다. 매일 03:30 의 귀속 보강
  (`scripts/enrich-backfill.sh` → `backfill_product_links`, 하루 6만 행)이 이제 같은
  폴백을 거치므로 약 17일에 걸쳐 코퍼스 전체에 반영된다.

**확인** (어느 경우든)

```bash
set -a; source .env; set +a
apptainer exec instance://sf_postgres psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" \
  -h 127.0.0.1 -p "${POSTGRES_PORT}" -c "
SELECT to_char(date_trunc('month', v.collected_at),'YYYY-MM') AS m,
       round(100.0*count(*) FILTER (WHERE p.is_active = false)/count(*),2) AS old_model_pct
FROM voc_records v LEFT JOIN products p ON p.id = v.product_id
WHERE v.archived_at IS NULL AND v.collected_at >= '2026-08-01'
GROUP BY 1 ORDER BY 1"
# 고장 상태: 8월 8% 대 → 9·10월 1~2% 로 꺼진다. 반영 후에는 9·10월이 다시 올라온다.
```
