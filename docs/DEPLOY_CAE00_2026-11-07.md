## 4. 들어왔는지 본다 · 재기동

dev 적용 뒤 첫 병합이 끝나면(출력의 `voc_product_links +… -…` 가 수만) 2절 dry-run 을 한 번 더 돌린다 — `고침` 이 0(또는
3절의 cae00 만 가진 글 몇)이어야 한다.

worker 나 sf-mcp 가 옛 코드면(update-all 이 다시 띄우지 않았거나 손으로 git pull 만 했으면) 다시 띄운다. 10-27 문서 1절처럼
워치독 락을 쥔다.

```bash
( exec 9>/tmp/sf-watchdog.lock; flock -w 90 9 && exec -a "watchdog.sh(maint-hold)" sleep 600 ) &
HOLD=$!
for inst in sf-crawler-worker sf-mcp; do
  apptainer instance stop $inst
  for t in $(seq 1 60); do ps -eo args | grep -q "[A]pptainer instance: $(id -un) \[$inst\]" || break; sleep 1; done
done
bash scripts/up.sh 2>&1 | grep -E "✓|⚠|→ instance|semantic"
kill $HOLD
```

**검증** — `✓ sf-mcp semantic import ok`. worker 가 뜬 뒤 30분 안에 `crawler/data/mv_refresh/` 에 MV 다섯 개(mv_voc_daily ·
category_daily · kg_edges_daily · platform_health · country_daily)의 기록 파일이 생긴다.
