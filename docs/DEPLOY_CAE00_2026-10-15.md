## 1. `.env` — `SIGNALFORGE_API` (중요도 높음)

`.env` 는 git 에 없다. 이 키가 없으면 **크롤러·인사이트 9개 모듈이 백엔드 대신
`:8000` 을 때린다.** dev 박스에서는 그 포트를 vLLM 이 쓰고 있어서 404 를 정중히
돌려줬고, 대시보드 워밍이 15분마다 8건을 남의 서비스에 쏘며 `warmed=0 failed=8`
로 조용히 '성공'했다(81일간). cae00 의 `:8000` 에 무엇이 있든, 백엔드는 아니다.

**확인**

```bash
grep -n '^SIGNALFORGE_API=' .env || echo "미설정"
grep -n '^API_PORT=' .env
```

**조치** — 없으면 추가한다. `API_PORT` 와 반드시 일치시켜라.

```bash
cat >> .env <<'EOF'
# 크롤러·인사이트 계층이 백엔드를 부를 때 쓰는 주소(API_PORT 와 맞춘다).
# **:8000 은 쓰지 마라** — 다른 서비스가 점유하면 404 를 정중히 돌려줘
# "연결 실패"조차 아닌 조용한 고장이 된다.
SIGNALFORGE_API=http://127.0.0.1:18000
EOF
```

코드 기본값도 `API_PORT` → `18000` 순으로 되어 있어 미설정이어도 동작하지만,
`.env` 에 명시해 두는 쪽이 안전하다(포트를 바꿀 때 한 곳만 보면 된다).

**검증**

```bash
set -a; source .env; set +a
curl -s -o /dev/null -w '%{http_code}\n' -H "X-API-Key: $API_KEY" \
  "http://127.0.0.1:${API_PORT}/api/v1/_internal/collection-status"
# 기대: 200
```

```bash
for i in $(seq 1 25); do ss -ltn | grep -q ":18000" || break; sleep 1; done
for i in $(seq 1 25); do ps -eo args | grep -q '[c]elery -A celery_app' || break; sleep 1; done
```

그래서 두 번 헛돌았다. 위 대기 루프를 빼지 마라.

### 3a. `50 4` 백업 검증 — 신규 (중요도 높음)

### 3b. `17 */8` YouTube — 주기 완화 (`*/6` 이었다)

독스트링의 quota 산수가 **질의 5개 시절 값**으로 실제와 3배 어긋나 있었다.

| | 질의 | 실행당 | 하루 |
|---|---|---|---|
| 정기수집 | 23 | 2,415u | ×4 = 9,660u |
| 백필 | 8 | 840u | ×1 = 840u |
| **합계** | | | **10,500u / 무료 10,000u = 105%** |

매일 마지막 실행이 `quotaExceeded` 로 조용히 죽는 상태였다. `*/8`(3회/일)로
낮추면 8,085u = 81%, 여유 1,915u 다.

**cae00 가 같은 API 키를 쓰면 합산해서 넘는다.** 확인하라.

```bash

# dev 박스와 같은 키면 두 박스 합계가 한도를 공유한다 —
# 한쪽을 끄거나 질의를 나눠라. 이건 내가 판단할 수 없다.
```

**검증**

```bash

# 이 테스트가 cron 주기와 질의 수를 곱해 한도×0.90 과 비교한다.
```

## 7. 전체 검증 — 적용 후 한 번에

```bash
# 서비스
for u in 18000/health 8013/mcp 17370/; do
  printf ':%-14s %s\n' "$u" \
    "$(curl -s -o /dev/null -w '%{http_code}' --max-time 10 "http://localhost:${u%%/*}/${u#*/}")"
done
# 기대: 200 / 401(인증 필요라 정상) / 200

# 인스턴스 6종
apptainer instance list | grep -c '^sf'      # 기대: 6
ps -eo args | grep -c '[c]elery -A celery_app worker'   # 기대: 1 이상
ps -eo args | grep -c '[c]elery -A celery_app beat'     # 기대: 1

# ⚠ 위 두 숫자가 어긋나면(프로세스는 있는데 인스턴스가 6 미만) **레지스트리
#   유실(고아)** 이다. ~/.apptainer/instances 의 항목만 사라지고 프로세스는
#   계속 사는 상태로, instance stop/exec 이 불가해진다. 프로세스 검사는
#   통과하므로 up.sh 도 다시 만들지 않아 **영구히 관리 불가로 남는다**
#   (dev 박스 2026-10-15 실측: sf-crawler-beat 가 그 상태였다 — 레지스트리 0,
#    프로세스 생존, 스케줄 파일은 정상 갱신. 돌긴 도는데 손댈 수 없었다).
#   복구는 supervisor 를 **PID 로** 끊고 up.sh 를 다시 부르는 것이다:
#     SUP=$(ps -eo pid,args | grep "[A]pptainer instance: $(id -un) \[sf-crawler-beat\]" | awk '{print $1}' | head -1)
#     kill -TERM "$SUP"; until ! ps -eo args | grep -q '[c]elery -A celery_app beat'; do sleep 1; done
#     bash scripts/up.sh
#   `pkill -f` 는 쓰지 마라 — 패턴이 자기 셸까지 잡는다(내가 세 번 겪었다).
#   649eb0c 이후의 watchdog.sh 는 이 고아 상태를 자동으로 감지해 끊는다.

# 워치독 (매분 heartbeat 갱신이 정상)
echo "$(( $(date +%s) - $(stat -c %Y logs/.watchdog-heartbeat 2>/dev/null || echo 0) ))초 전"
# 기대: 60초 이내. 파일이 없거나 오래됐으면 watchdog 이 안 도는 것이다.

# 감시 태스크가 산출물을 내는가
find reports -maxdepth 1 -type f -mtime -1 | wc -l    # 기대: 1 이상
#  ⚠ `-newermt '-1 day'` 는 쓰지 마라 — 내가 그 문법으로 0 을 받아
#    "감시가 죽었다"고 오판했다. `-mtime` 을 쓴다.
```

## 8. 적용하지 않아도 되는 것 (코드로 끝남)

`git pull` 만으로 적용된다. 참고용.

- **제품 키워드 검색 정밀도 50% → 100%** — `plainto_tsquery` 가 `"S25 Ultra"` 를
  `'s25' & 'ultra'` 로 바꿔 글 전체에서 따로 찾았다. 구절 검색으로 바꿨다.
  MCP 도구 `resolve_product_keyword` 가 추가됐다(표기가 달라도 같은 제품 코드로
  수렴한다 — 자유 텍스트는 표기에 따라 88~9,680건으로 100배 흔들린다).
- **터키어 İ KeyError** — `'Pİxel'.lower()` 가 결합문자를 만들어 제품 매칭이
  `KeyError` 로 크롤 프로세스를 죽였다. 나흘간 Reddit 역사 수집이 0이었다.
- **워치독 락 fd 상속** — 데몬이 락을 물려받아 워치독이 일주일간 조용히
  `exit 0` 했다. 누수된 락을 스스로 끊고, beat 도 점검한다.
- **백필 자식 11개 rc 전파 + 커서 가드** — 실패해도 커서가 전진해 DB 다운
  나흘간 HN 이 2013~2010년을 빈손으로 소비했다.
- **알림 묶기** — 사이트별 발화를 종류 3개로 묶고 "새로 죽은 사이트가 생겼을
  때만" 발화한다. 하루 280건 → 2~6건.
