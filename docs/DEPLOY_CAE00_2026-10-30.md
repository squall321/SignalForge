## 1. 재기동 — sf-mcp · sf-backend

sf-mcp 가 새 검색·주의를 읽고, sf-backend 는 한글 부분일치 변경(`shared/keyword_match.py`)을 읽는다. 10-27 문서 1절처럼
워치독 락을 쥐고 하나씩 멈춘 뒤 up.sh.

```bash
( exec 9>/tmp/sf-watchdog.lock; flock -w 90 9 && exec -a "watchdog.sh(maint-hold)" sleep 600 ) &
HOLD=$!
for i in sf-mcp sf-backend; do
  apptainer instance stop "$i"
  for t in $(seq 1 60); do ps -eo args | grep -q "[A]pptainer instance: $(id -un) \[$i\]" || break; sleep 1; done
done
bash scripts/up.sh 2>&1 | grep -E "✓|⚠|→ instance|semantic"
kill $HOLD
```

**검증** — `✓ sf-mcp semantic import ok`.

PLM 거울은 다시 받지 않아도 된다 — 별칭은 거울 파일의 properties 에 이미 있고 색인이 읽을 때 꺼낸다.

## 3. SG-04 결정에 쓸 수 — 안 A 의 다시 태깅 범위

포털 묻는 글(`docs/request-1029/signalforge-sg04-question.md`)의 안 A 는 'PH8 코드로 태깅된 글 가운데 P8 인 것' 을 다시
태깅한다. 실제 이름은 cae00 에만 있으니 거기서 센다.

```bash
PGPASSWORD=$POSTGRES_PASSWORD apptainer exec instance://sf_postgres psql -h 127.0.0.1 -p $POSTGRES_PORT -U $POSTGRES_USER -d $POSTGRES_DB -c "
SELECT count(*) AS ph8_rows,
       count(*) FILTER (WHERE v.content_original ILIKE ANY(ARRAY['%<P8 한국어 마케팅명>%'])
                           OR v.content_translated ILIKE ANY(ARRAY['%<P8 영문 마케팅명>%'])) AS mention_p8
FROM voc_product_links l JOIN voc_records v ON v.id = l.voc_id JOIN products p ON p.id = l.product_id
WHERE p.code = '<PH8 의 제품 코드>' AND v.archived_at IS NULL;"
```

`mention_p8` 가 안 A 의 다시 태깅 상한이다(이름이 나온 글 — P8 이 맞는지는 표본으로 본다). 결정(A · B · C)은 사용자 몫이다.

## 4. 남은 결정 — SG-19 를 더 줄이려면

지금 고친 것은 스키마를 건드리지 않았다. 한국어 글은 활성의 14%(본문 30~38MB)뿐인데 그 글만 고를 색인이 없어 한국어
원문 경로가 늘 voc_records 전체를 읽는다. 한국어 글만 담은 좁은 표(또는 색인)를 두면 같은 훑기가 0.43초다(같은 때 전체
훑기는 127초, dev 실측). 마이그레이션 · 쓰기 길목 유지가 드는 스키마 변경이라 사용자 결정으로 남긴다.
