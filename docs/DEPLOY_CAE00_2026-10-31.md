## 3. 다시 태깅 적용 — dev 에서 한다 (cae00 에서는 `--apply` 하지 않는다)

cae00 의 병합은 dev 가 아는 글의 대표(product_id)와 링크를 **dev 와 같게** 맞춘다(dev 가 뗀 링크는 뗀다 —
`merge-from-drive.sh` 머리말). cae00 에서만 고치면 다음 병합이 dev 의 옛 태깅으로 되돌린다. 그래서 2절 확인이 오면 dev 쪽
세션이 원본에 적용하고, 30분 덤프와 cae00 병합으로 들어온다. dev 쪽 순서(참고)는 아래와 같다.

1. dev 수집 worker 재기동 — 그 뒤 새 글은 새 매처로 태깅된다
2. `python3 -m scripts.retag_split --from GZF8 --to GZF8U --apply --log logs/retag-split-GZF8-GZF8U-apply.csv` — 되돌리기 CSV
3. dev sf-mcp 재기동

병합은 dev 덤프에 없는 행(이 서버가 모았거나 병합 뒤 dev 가 지운 글 — 병합 출력의 `dev 덤프에 없는 행`)은 건드리지
않는다. 그 수가 0 이 아니면 4절의 dry-run 다시 돌리기에 남는 고침이 그 글이다 — 그 글만 cae00 에서 2절 명령에
`--apply` 를 붙여 돌린다(이미 나뉜 글은 다시 돌려도 그대로다).

## 4. 들어왔는지 본다 — sf-mcp 가 옛 코드면 재기동

dev 적용 뒤 첫 병합이 끝나면(출력의 `voc_records ~…` · `voc_product_links +… -…` 가 수천) 수를 본다.

```bash
PGPASSWORD=$POSTGRES_PASSWORD apptainer exec instance://sf_postgres psql -h 127.0.0.1 -p $POSTGRES_PORT -U $POSTGRES_USER -d $POSTGRES_DB -c "
SELECT p.code,
  (SELECT count(*) FROM voc_records v WHERE v.product_id = p.id AND v.archived_at IS NULL) AS primary_active,
  (SELECT count(*) FROM voc_product_links l JOIN voc_records v ON v.id = l.voc_id
    WHERE l.product_id = p.id AND v.archived_at IS NULL) AS links_active
FROM products p WHERE p.code IN ('GZF8','GZF8U') ORDER BY p.code;"
# 기대 — 2절 표의 '적용 뒤' 언저리(GZF8U 대표 6천여 · 링크 9천여)
```

2절 dry-run 을 한 번 더 돌리면 `고침` 이 0(또는 3절의 cae00 만 가진 글 몇)이어야 한다.

update-all 로 이미 새 코드로 떠 있으면 재기동은 필요 없다 — 병합이 들어오는 대로 5절이 맞는다. 손으로 git pull 만 했으면
여기서 sf-mcp 만 재기동한다(sf-backend 는 이번에 바뀐 매처 · 온톨로지를 쓰지 않는다). 10-27 문서 1절처럼 워치독 락을 쥔다.

```bash
( exec 9>/tmp/sf-watchdog.lock; flock -w 90 9 && exec -a "watchdog.sh(maint-hold)" sleep 600 ) &
HOLD=$!
apptainer instance stop sf-mcp
for t in $(seq 1 60); do ps -eo args | grep -q "[A]pptainer instance: $(id -un) \[sf-mcp\]" || break; sleep 1; done
bash scripts/up.sh 2>&1 | grep -E "✓|⚠|→ instance|semantic"
kill $HOLD
```

**검증** — `✓ sf-mcp semantic import ok`.

## 6. 남은 것 · 결정 몫

- **GZF8 의 앞 세대** — 비웠다(0046). GZF7 을 잇는 것은 GZF8U 뿐이고, 넓은 폼팩터는 결함 급등 기준선 · 라이프사이클
  주차 비교에서 앞 세대 없는 새 계열로 센다. 병합으로 들어온다(1절).
- **모델코드 사전** — 옮겼다(`SM-F976…` → GZF8U, `SM-F971…` → GZF8). 4절의 sf-mcp 재기동 뒤 모델코드로 물으면 그 기기로
  풀린다(5절). 지난 글은 2절 · 3절의 같은 다시 태깅으로 간다.
- **이름만으로 안 갈리는 글** — 그냥 'Fold8 · 폴드8' 이라고 쓴 글은 GZF8 에 남는다. 출시 전(2026-07 이전) 2,177행은 소문
  시기 글이라 어느 기기를 말하는지 글만으로는 모른다. 2절 dry-run 의 표본과 수를 본 뒤 더 가를지 정한다.
