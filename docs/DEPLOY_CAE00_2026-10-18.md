# cae00 배포 적용 체크리스트 — 2026-10-18

이 문서는 **cae00(배포서버)에서 작업하는 AI/운영자**를 대상으로 한다.
[2026-10-17 체크리스트](DEPLOY_CAE00_2026-10-17.md)를 먼저 적용하라. 이 문서는 그 뒤의 한 가지다.

각 항목은 `확인` → `조치` → `검증` 순이다. 아래 수치는 모두 dev 박스 실측값이다.

## 무엇이 바뀌었나

**PostgreSQL `shared_buffers` 를 `.env` 로 올릴 수 있게 했다** (`a98b154`). 사용자 결정 —
cae00 은 메모리 여유가 있으니 올린다. dev 는 스왑이 꽉 차(39/39GB, 외부 프로세스) 기본값 128MB 를
그대로 둔다.

왜 — 기본값 128MB 는 읽기의 거의 전부를 OS 페이지 캐시에 기댄다. dev 에서 캐시가 갈리면
브랜드·전역 시맨틱 검색('갤럭시 …', '삼성 …', 제품 없는 증상)이 6~16초 걸렸다(따뜻하면 1초).
dev 의 누적 버퍼 적중률은 53.9% — 10-10 기동 이후 커널에서 읽은 블록이 69억 개(약 57TB)다.

동작 — `PG_SHARED_BUFFERS` 가 비어 있으면 아무것도 바꾸지 않는다. 값이 있으면 `scripts/up.sh` 가
**꺼져 있던 postgres 를 띄울 때만** `data/postgres/pgdata/postgresql.auto.conf` 에 쓴다(ALTER SYSTEM 과
같은 파일·형식). 떠 있는 DB 는 재기동하지 않고 `[NOTE]` 로 알리기만 한다. 쓸 때 남기는
`postgresql.auto.conf.sf-bak` 은 "아직 그 값으로 뜨는 걸 못 본 변경"이다 — 뜨면 지우고, postgres 가
죽어 버리면 그 파일로 되돌려 다시 띄운다. 바꾼 실행이 중간에 끊겨도 다음 up.sh(워치독 포함)가
되돌린다. 복구(redo) 중이라 늦게 뜨는 서버는 되돌리지 않는다.

이 설정은 cae00 에 남는다 — auto-pull 의 복원은 `DROP DATABASE` + `psql` 이라 `postgresql.auto.conf` 를
건드리지 않고, Drive 동기화는 `.env.example` 만 받지 `.env` 를 덮지 않는다.

## 0. 코드 받기

```bash
git pull origin main
git log --oneline -15 | grep -E "a98b154|62d3fb4"
# 기대: 두 줄 보인다
grep -n "PG_SHARED_BUFFERS" .env.example scripts/up.sh | head -3
```

## 1. 확인 — 지금 값과 메모리

```bash
set -a; source .env; set +a
free -g | head -2
apptainer exec --env PGPASSWORD="$POSTGRES_PASSWORD" instance://sf_postgres \
  psql -h 127.0.0.1 -p "$POSTGRES_PORT" -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tAc "
SHOW shared_buffers;
SELECT pg_size_pretty(pg_database_size(current_database()));
SELECT now(), blks_hit, blks_read,
       round(100.0*blks_hit/nullif(blks_hit+blks_read,0),1) AS hit_pct
FROM pg_stat_database WHERE datname = current_database();"
# 마지막 줄(시각·hit·read)을 적어 둔다 — 4절에서 하루 뒤와 비교한다
```

`128MB` 면 아직 기본값이다. 이미 원하는 값이면 여기서 끝.

## 2. 값 고르기

| cae00 MemTotal (`free -g` 의 total) | `PG_SHARED_BUFFERS` |
|---|---|
| 32GB 이상 | `4GB` — dev 기준 DB 3.5GB(주로 읽히는 voc_records 1.5GB)가 통째로 든다 |
| 16~32GB | `2GB` |
| 8~16GB | `1GB` |
| 8GB 미만 | 올리지 않는다 |

1절의 DB 크기가 dev(3.5GB)보다 훨씬 크면 그만큼 키워도 되지만 MemTotal 의 25% 를 넘기지 마라.
up.sh 는 40% 를 넘는 값은 쓰지 않고 `[WARN]` 만 낸다. 단위는 PostgreSQL 표기(`kB`·`MB`·`GB`, 대소문자
그대로)의 정수만 받는다 — `4G`·`4gb`·`2.5GB` 는 거부된다.

## 3. 조치

```bash
V=4GB    # 2절에서 고른 값
grep -q '^PG_SHARED_BUFFERS=' .env \
  && sed -i "s/^PG_SHARED_BUFFERS=.*/PG_SHARED_BUFFERS=$V/" .env \
  || echo "PG_SHARED_BUFFERS=$V" >> .env
grep '^PG_SHARED_BUFFERS=' .env

# 한가한 시간에. 두 명령을 한 줄로 붙여 실행한다(사이에 워치독이 끼어들 틈을 줄인다).
apptainer instance stop sf_postgres && bash scripts/up.sh
```

up.sh 출력에 다음 두 줄이 보여야 한다.

```
→ shared_buffers = 4GB (postgresql.auto.conf, 원본은 .sf-bak)
✓ postgres ready (Ns)
```

- DB 가 수 초 끊긴다. 앱(backend·mcp·worker)은 다시 붙는다. 그 사이 돌던 수집 태스크 한두 개가
  실패할 수 있고 다음 주기에 다시 돈다.
- `[ERROR] shared_buffers=… 로 postgres 가 안 뜬다 — 원래 설정으로 되돌려 다시 띄운다` 가 보이면
  메모리를 못 잡은 것이다. up.sh 가 이미 원래 값으로 띄웠다. 2절 표에서 한 단계 낮춰 3절을 다시 한다.
- 워치독 tick 이 겹쳐 up.sh 하나가 `instance already exists` 로 끝나도 무해하다 — 다른 하나가 띄운다.
  4절 검증으로 확인한다.

## 4. 검증

```bash
apptainer exec --env PGPASSWORD="$POSTGRES_PASSWORD" instance://sf_postgres \
  psql -h 127.0.0.1 -p "$POSTGRES_PORT" -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tAc "SHOW shared_buffers"
# 기대: 3절의 값 (예: 4GB)
bash scripts/up.sh 2>&1 | grep -E "NOTE|WARN|ERROR"
# 기대: 아무것도 안 나온다(값이 맞으면 알림이 없다). 서비스 PID 도 그대로다.
```

하루쯤 뒤 1절의 마지막 쿼리를 다시 돌려 **두 시점의 차이로** 적중률을 본다.

```
적중률 = (hit₂ − hit₁) / ((hit₂ − hit₁) + (read₂ − read₁))
```

누적값(`hit_pct`)은 기동 이후 전체라 잘 안 움직인다. 차이로 보라. dev(128MB)는 누적 53.9% 였다.

## 5. 되돌리기 (필요할 때만)

`.env` 에서 지우기만 하면 **되돌아가지 않는다** — 값은 `postgresql.auto.conf` 에 남아 있다.

```bash
sed -i '/^PG_SHARED_BUFFERS=/d' .env
sed -i '/^shared_buffers[[:space:]]*=/d' data/postgres/pgdata/postgresql.auto.conf
apptainer instance stop sf_postgres && bash scripts/up.sh
# SHOW shared_buffers → 128MB
```

## 참고

- dev 는 이 설정을 쓰지 않는다(`.env` 에 없음). dev 스왑이 풀리면 같은 방법으로 올릴 수 있다.
- 새로 initdb 한 DB 는 첫 기동 때 `postgresql.auto.conf` 가 없어 값을 못 쓴다 — `[NOTE]` 가 나오면
  한 번 더 `apptainer instance stop sf_postgres && bash scripts/up.sh`. cae00 처럼 기존 DB 면 해당 없다.
- 검증 스크립트: `bash scripts/tests/test_pg_shared_buffers.sh`(단위 25). `SF_PG_IT=1` 이면 임시
  postgres 인스턴스로 실제 기동·실패·복구와, up.sh 의 postgres 구간 그대로(새 DB 알림·적용·끊긴 변경
  되돌리기)까지 본다(33). 운영 DB·인스턴스는 건드리지 않는다.
